# PawnSteps 架构与业务约定

## 分层与状态契约

FastAPI 路由负责 Pydantic 参数校验、认证依赖与响应序列化；业务服务负责事务、跨天处理和租户校验；SQLAlchemy 模型负责持久化约束。前端只访问 REST API，后续原生客户端可以复用同一套接口。数据库结构由 Alembic 管理。

业务写请求返回 `MutationResponse`，包含 `tasks`、`rewards`、`stats`、`unlocked_reward`。认证、上传、删除等接口在此基础上增加自身结果。前端一次响应更新全部业务状态，避免任务完成后奖励和统计落后。GET 读取任务也会执行日期协调，因此必须允许事务提交。

`owner_id` 是所有业务访问的边界：登录用户为 `user:<uuid>`，游客为 `guest:<uuid-v4>`。客户端请求不能直接指定 owner；后端根据 Bearer JWT 或 `X-Guest-Id` 生成 owner。已有 Authorization 但令牌无效时拒绝请求，不回退为游客。管理员使用独立的令牌 audience 和认证入口。

## 日期和进度

统一使用服务端配置的业务时区（默认 Asia/Shanghai）判定“今天”，时间戳按 UTC 保存。跨时区用户共享这一业务日边界；如需每用户时区，应增加用户字段并明确迁移策略。

普通任务的目标为 1–100，支持自定义单位。普通任务也可设置 `daily_minimum`，达到每日最低量会生成当日达标记录并参与连续天数，但总进度仍按数量累加，不改成天数任务。每次追加完成量与备注，进度由有效记录之和计算，展示值不超过目标；不再提供任意设置总进度的入口。每日任务的目标为需要完成的天数，每日配额单独记录；同一天可以追加多次，但达标只累计一次。修改或撤销一条历史记录会重新计算当日达标、连续天数和 XP。

计划任务的目标为正配额之和，进度按实际配额单位累计。零和负一代表休息，休息日自动产生完成记录。计划到期仍结束，但进度保留实际完成量，不会自动补满；响应通过 `plan_expired` 区分计划到期。每天的计划贡献以当天配额封顶，记录本身保留真实完成量。历史配额在 `daily_history.quota` 中按日期冻结，修改现在的每日配额不会重新解释过去的达标。

新增 `progress_records` 表保存数量、备注、业务日期、来源、创建/修改时间及撤销时间。记录通过所属任务隔离 owner，游客迁移和任务撤销删除保留其关联。创建记录的请求 ID 具有唯一约束，重试不会重复累计；撤销保留内部记录，数据导出包含这些痕迹。旧版累计由迁移标记为 legacy，未知工作日期保持为空。

课程条目保留文件夹标记（名称以 `/` 结尾），但目标、进度、批量勾选均只计算实际条目。文件夹分组优先；没有文件夹时按 25 项分组。桌面框选与普通勾选使用同一个批量更新接口。

连续天数严格从今天开始倒查；今天没有达标记录则为零。每日任务按每日最低量（daily_quota）判断，计划任务按当天配额判断；计划休息日保持自动达标。日历独立展示任意正向进度，包括普通任务和带日期的课程勾选；区分未做、低于最低量、达标和超额。休息日不补造实际进度，旧课程勾选没有日期的部分不补造日期。六个里程碑按租户和天数唯一创建。奖励解锁作为已获得的奖励保留，撤销任务进度不会自动收回自定义奖励。

## 删除与恢复

删除后立即从列表隐藏，返回不可预测且绑定 owner 的撤销令牌。服务端按 5 秒窗口校验恢复请求。超过窗口的删除不可恢复；不以浏览器计时为授权依据。历史记录随最终删除的任务级联清理。

## 身份和存储

密码使用 bcrypt；JWT 采用 HS256，30 天有效期。用户令牌含版本号，修改密码可使旧令牌失效。邮箱验证码只保存摘要，控制有效期、尝试次数和请求频率。微信网站登录需配置已审核的网站应用及回调域名。

图片先检验格式、大小和像素，再解码重编码，剥离原文件内容与元数据。开发可写本地卷，生产可配置 S3 与公开 CDN 地址；上传后的文件名由服务器生成。

## 部署边界

生产栈为 Nginx、Next.js standalone、FastAPI 和 PostgreSQL。迁移作为独立的一次性服务先于后端启动。外网只暴露 Nginx；生产域名的 HTTPS 由入口网关或反向代理终止。数据库与上传卷需要独立备份。

`is_premium` 是需求约定的预留字段。当前功能清单未指定支付渠道、价格、订阅周期或退款规则，因此不包含支付扣款和订阅计费。

每日数量分为最小完成量和每日目标量：`daily_minimum`（普通目标）或 `daily_quota`（每日任务）决定达标和连续天数，`daily_goal` 是期望每天完成的数量，不改变达标底线。普通任务的 `target` 保持累计总量；每日任务的 `target` 保持坚持天数。卡片默认仅显示“今日完成量 / 每日目标量”，普通目标下方保持总进度条；最小完成量、完整累计数据和优先级收进任务详情。课程仅在学习进度条旁显示节数，避免重复。

课程每日计划复用 `daily_minimum`、`daily_goal` 和日期化的课程勾选。达到最小节数计为达标，课程总进度始终按实际条目累计并排除文件夹。旧课程不会自动启用计划，未保存完成日期的旧勾选不补造日期。编辑最小量只更新今日门槛，历史门槛保持不变。新建课程默认启用每日学习计划，可关闭；普通课程界面仍保留完整的导入、分组和框选功能。打开课程定位下一节未完成条目，交互过程中不自动跳转；“定位下一节”支持重新展开对应分组和键盘聚焦。
