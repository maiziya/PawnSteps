# PawnSteps 架构与业务约定

## 分层与状态契约

FastAPI 路由负责 Pydantic 参数校验、认证依赖与响应序列化；业务服务负责事务、跨天处理和租户校验；SQLAlchemy 模型负责持久化约束。前端只访问 REST API，后续原生客户端可以复用同一套接口。数据库结构由 Alembic 管理。

业务写请求返回 `MutationResponse`，包含 `tasks`、`rewards`、`stats`、`unlocked_reward`。认证、上传、删除等接口在此基础上增加自身结果。前端一次响应更新全部业务状态，避免任务完成后奖励和统计落后。GET 读取任务也会执行日期协调，因此必须允许事务提交。

`owner_id` 是所有业务访问的边界：登录用户为 `user:<uuid>`，游客为 `guest:<uuid-v4>`。客户端请求不能直接指定 owner；后端根据 Bearer JWT 或 `X-Guest-Id` 生成 owner。已有 Authorization 但令牌无效时拒绝请求，不回退为游客。管理员使用独立的令牌 audience 和认证入口。

## 日期和进度

统一使用服务端配置的业务时区（默认 Asia/Shanghai）判定“今天”，时间戳按 UTC 保存。跨时区用户共享这一业务日边界；如需每用户时区，应增加用户字段并明确迁移策略。

普通任务的目标为 1–100，进度按步数累计。每日任务的目标为需要完成的天数，每日配额单独记录；同一天达标只累计一次，撤销当日达标会撤回当天贡献和历史记录状态。

计划任务的目标为正配额之和，进度按实际配额单位累计。零和负一代表休息，休息日自动产生完成记录。计划结束后整个任务自动完成，这是需求指定的时间边界，与是否补足此前配额分别处理。历史记录额外保存当天进度，保证撤销与跨天后仍能计算实际贡献。

课程条目保留文件夹标记（名称以 `/` 结尾），但目标、进度、批量勾选均只计算实际条目。文件夹分组优先；没有文件夹时按 25 项分组。桌面框选与普通勾选使用同一个批量更新接口。

连续天数严格从今天开始倒查；今天没有完成记录则为零。某天任一每日任务或计划任务达标就算该天有记录。六个里程碑按租户和天数唯一创建。奖励解锁作为已获得的奖励保留，撤销任务进度不会自动收回自定义奖励。

## 删除与恢复

删除后立即从列表隐藏，返回不可预测且绑定 owner 的撤销令牌。服务端按 5 秒窗口校验恢复请求。超过窗口的删除不可恢复；不以浏览器计时为授权依据。历史记录随最终删除的任务级联清理。

## 身份和存储

密码使用 bcrypt；JWT 采用 HS256，30 天有效期。用户令牌含版本号，修改密码可使旧令牌失效。邮箱验证码只保存摘要，控制有效期、尝试次数和请求频率。微信网站登录需配置已审核的网站应用及回调域名。

图片先检验格式、大小和像素，再解码重编码，剥离原文件内容与元数据。开发可写本地卷，生产可配置 S3 与公开 CDN 地址；上传后的文件名由服务器生成。

## 部署边界

生产栈为 Nginx、Next.js standalone、FastAPI 和 PostgreSQL。迁移作为独立的一次性服务先于后端启动。外网只暴露 Nginx；生产域名的 HTTPS 由入口网关或反向代理终止。数据库与上传卷需要独立备份。

`is_premium` 是需求约定的预留字段。当前功能清单未指定支付渠道、价格、订阅周期或退款规则，因此不包含支付扣款和订阅计费。
